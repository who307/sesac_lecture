## 1. useMemo

연산의 **결과값**을 메모리에 저장(캐싱)하여, 의존성 배열에 명시한 값이 바뀌지 않는 한 이전 연산 결과를 그대로 재사용합니다.

JavaScript

# 

```
import React, { useState, useMemo } from 'react';

function UseMemoExample(){
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  // [핵심] count가 변경될 때만 무거운 연산을 다시 실행합니다.
  // text 입력으로 인해 컴포넌트가 재렌더링될 때는 이전 연산 결과(calcResult)를 재사용합니다.
  const calcResult = useMemo(() => {
    console.log('🔥 무거운 연산 실행 중...');
    let sum = 0;
    for (let i = 0; i < 100000000; i++) {
      sum += count;
    }
    return sum; // 렌더링 시 사용할 '값'을 반환
  }, [count]); // 의존성 배열: count가 변할 때만 캐시를 갱신함

  return (
    <div>
      <h2>useMemo 예시</h2>
      {/* text를 입력하면 state 변경으로 재렌더링이 일어나지만, calcResult 연산은 스킵됩니다 */}
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        placeholder="글자를 입력해보세요"
      />

      {/* count가 증가할 때만 useMemo 내부 함수가 재실행됩니다 */}
      <button onClick={() => setCount(count + 1)}>Count 증가: {count}</button>
      <p>연산 결과: {calcResult}</p>
    </div>
  );
}
```

## 2. useCallback

함수 객체 자체의 참조(주소값)를 메모리에 보관합니다. 컴포넌트가 재렌더링되더라도 의존성 배열의 값이 변하지 않았다면 동일한 함수 참조를 유지합니다. (`React.memo`로 최적화된 자식 컴포넌트에 콜백 함수를 넘길 때 유용합니다.)

JavaScript

# 

```
import React, { useState, useCallback } from 'react';

// React.memo: 전달받는 prop(onClick)이 변경되지 않으면 재렌더링을 방지합니다.
const ChildButton = React.memo(({ onClick }) => {
  console.log('👶 자식 컴포넌트 렌더링됨');
  return <button onClick={onClick}>자식 버튼</button>;
});

function UseCallbackExample(){
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  // [핵심] 함수 생성 자체를 메모이제이션하여 참조 주소를 유지합니다.
  // useCallback을 쓰지 않으면 text가 바뀔 때마다 새로운 함수 객체가 생성되어
  // 자식 컴포넌트(ChildButton)가 불필요하게 재렌더링됩니다.
  const handleClick = useCallback(() => {
    console.log('자식 버튼 클릭됨!');
  }, []); // 빈 배열: 최초 렌더링 시 생성된 함수 참조를 계속 재사용함

  return (
    <div>
      <h2>useCallback 예시</h2>
      {/* text가 변경되어 부모가 재렌더링되어도 handleClick의 주소는 그대로 유지됩니다 */}
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        placeholder="글자를 입력해보세요"
      />
      <button onClick={() => setCount(count + 1)}>부모 Count: {count}</button>

      {/* handleClick 참조값이 동일하므로 ChildButton은 재렌더링되지 않습니다 */}
      <ChildButton onClick={handleClick} />
    </div>
  );
}
```

## 3. useRef

두 가지 목적(DOM 접근, 렌더링을 일으키지 않는 값 저장)으로 사용하며, `.current` 프로퍼티를 통해 값에 접근하고 변경할 수 있습니다.

JavaScript

# 

```
import React, { useState, useRef } from 'react';

function UseRefExample(){
  const [renderCount, setRenderCount] = useState(0);

  // [용도 1] DOM 요소 직접 참조 (inputRef.current)
  const inputRef = useRef(null);

  // [용도 2] 렌더링에 영향을 주지 않는 변수 관리 (countRef.current)
  // 값이 바뀌어도 컴포넌트가 재렌더링되지 않고, 재렌더링되더라도 값이 유지됩니다.
  const countRef = useRef(0);

  const handleFocus = () => {
    // inputRef.current는 실제 DOM <input> 요소를 가리킵니다.
    inputRef.current.focus();
  };

  const handleRefIncrement = () => {
    countRef.current += 1; // 내부 값을 변경하지만 화면은 다시 그려지지 않습니다.
    console.log(`Ref 현재 값: ${countRef.current} (화면은 렌더링 안 됨)`);
  };

  return (
    <div>
      <h2>useRef 예시</h2>

      {/* 1. DOM 참조 연결 */}
      <input ref={inputRef} placeholder="여기에 포커스가 잡힙니다" />
      <button onClick={handleFocus}>포커스 이동</button>

      <hr />

      {/* 2. 렌더링을 일으키지 않는 값 확인 */}
      <p>Ref 저장값: {countRef.current}</p>
      <button onClick={handleRefIncrement}>Ref 값 증가 (화면 변화 X)</button>

      {/* State를 변경해 컴포넌트를 강제로 재렌더링하면 변경되었던 Ref 값이 화면에 반영됩니다 */}
      <button onClick={() => setRenderCount(renderCount + 1)}>
        컴포넌트 재렌더링 (State: {renderCount})
      </button>
    </div>
  );
}
```

## 결론

세 훅 모두 근본적으로 "리액트의 리렌더링 주기(Lifecycle) 속에서 값과 참조(Reference)를 어떻게 다룰 것인가"를 핸들링하기 위해 사용합니다.

조금 더 세부적으로 나누면 **리렌더링과의 관계**에 따라 두 그룹으로 구분할 수 있습니다.

### 1. `useMemo` & `useCallback`: "불필요한 연산과 자식의 리렌더링을 방지"

이 두 훅은 리액트가 리렌더링될 때 **불필요한 작업이 반복되는 것을 막는 캐싱(기억) 도구**입니다.

- **값/함수의 참조 유지**: 리액트는 컴포넌트가 다시 그려질 때 내부 변수와 함수를 새로 선언합니다. 이 때 `useMemo`는 **연산 결과값**의 참조를, `useCallback`은 **함수 자체**의 참조(주소값)를 유지시킵니다.
- **자식 컴포넌트 리렌더링 차단**: 자식 컴포넌트에 prop으로 객체나 함수를 전달할 때, 참조값이 매번 바뀌면 자식도 같이 리렌더링됩니다. 두 훅으로 참조를 고정해두면 자식 컴포넌트의 불필요한 리렌더링을 막을 수 있습니다.

### 2. `useRef`: "리렌더링을 일으키지 않는 값 할당"

`useRef`는 `useState`처럼 **값을 저장하고 할당**하지만, **리렌더링과의 관계를 끊어낸 도구**입니다.

- **독립적인 값 보관**: `useState`는 값이 변경되면 화면을 다시 그리지만(리렌더링), `useRef`는 `.current` 내부 값이 변경되어도 **리렌더링을 일절 일으키지 않습니다.**
- **컴포넌트 생명주기 동안 유지**: 일반 변수(`let`, `const`)는 리렌더링 시 초기화되지만, `useRef`에 담긴 값은 컴포넌트가 사라질 때(Unmount)까지 안전하게 유지됩니다.

### 한눈에 보는 비교

| **구분** | **값 할당/보관 방식** | **리렌더링과의 관계** |
| --- | --- | --- |
| **`useMemo`** | 연산된 **결과 값**을 보관 | **연산 방지** & 자식 컴포넌트의 불필요한 리렌더링 방지 |
| **`useCallback`** | **함수의 참조(주소값)**를 보관 | **함수 재선언 방지** & 자식 컴포넌트의 불필요한 리렌더링 방지 |
| **`useRef`** | **가변 변수** 및 **DOM 객체**를 보관 | 값 변경 시 **자기 자신의 리렌더링을 일으키지 않음** |

정리하자면, **리액트가 '화면을 다시 그리는 특성' 때문에 발생하는 값의 손실이나 불필요한 연산을 제어하기 위해** 이 세 가지 훅을 사용합니다.
